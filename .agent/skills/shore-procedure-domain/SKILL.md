# 🚢 Shore Procedure Domain Knowledge & Workflow Guidelines

ทักษะนี้รวบรวมบริบททางธุรกิจ (Business Domain) คำศัพท์เฉพาะทาง และตรรกะการทำงานของการจ่ายชอร์ (Shore Procedure) เพื่อให้การพัฒนาระบบสอดคล้องกับการทำงานจริงของพนักงานหน้าท่าเรือ

---

## 📚 1. คำศัพท์เฉพาะทาง (Glossary)

* **การจ่ายชอร์ (Shore Procedure / Shore Handling):** กระบวนการยื่นเอกสาร ชำระค่าธรรมเนียม หรือขออนุมัติปล่อยตู้สินค้า/รับตู้สินค้าผ่านท่าเรือและสายเรือ
* **ท่าเรือ (Ports / Terminals):** สถานที่รับ-ส่งตู้สินค้า เช่น ท่าเรือแหลมฉบัง C1C2, B3, A0, B5 ฯลฯ แต่ละท่ามีระบบสารสนเทศ ระเบียบการ และเคาน์เตอร์บริการของตนเอง
* **เอเย่นต์เรือ / สายเรือ (Shipping Agents / Lines):** ตัวแทนสายการเดินเรือ เช่น WHL (Wan Hai), ONE (Ocean Network Express), MSC, Evergreen, SITC ซึ่งมีข้อกำหนดในการตรวจปล่อยตู้สินค้าและเอกสารต่างกัน
* **เงื่อนไข / กรณี (Procedure Variants):** สถานการณ์ในการทำงานจริง เช่น:
  - **กรณีปกติ (Normal / Online):** จ่ายผ่าน e-Portal ของท่า/สายเรือ
  - **กรณีระบบขัดข้อง (System Down / Emergency):** ต้องส่งเอกสารผ่าน LINE หรืออีเมลฉุกเฉิน
  - **กรณีต้องยื่นหน้าท่า (On-site / Physical Document):** กรณีต้องนำเอกสารตัวจริง (เช่น Original B/L, ใบเสร็จตัวจริง) ไปประทับตราที่เคาน์เตอร์หน้าท่า
* **เวลาตัดรอบ (Cut-off Time):** เวลาเดดไลน์ที่ต้องจ่ายชอร์หรือยื่นเอกสารให้ทันรอบเรือ/รอบปล่อยตู้ หากเลยเวลานี้ตู้จะไม่ได้รับการปล่อยตามรอบ
* **ขั้นตอนปฏิบัติงาน (Procedure Steps):** รายการขั้นตอน 1, 2, 3... ที่พนักงานต้องทำตาม พร้อมคำอธิบายและรูปภาพประกอบหน้าจอจริง

## 🧭 2. โครงสร้างความสัมพันธ์ของข้อมูล (Data Hierarchy)

```text
[ท่าเรือ (Port)] + [เอเย่นต์ (Agent)] + [ประเภทงาน (Work Type)]
                          │
                          ▼
             [คู่มือหลัก (Procedure)]
                          │
        ┌─────────────────┴─────────────────┐
        ▼                                   ▼
[เงื่อนไข 1: ปกติ]                  [เงื่อนไข 2: ระบบล่ม]
        │                                   │
  ├── ขั้นตอน 1 (รูป 1, รูป 2)          ├── ขั้นตอน 1 (รูป 1)
  ├── ขั้นตอน 2 (รูป 1)                 └── ขั้นตอน 2 (รูป 1, รูป 2)
  └── ขั้นตอน 3
```

## 💡 3. กฎทางธุรกิจที่ต้องคำนึงถึง (Business Logic Rules)

1. **ห้ามสร้างคู่มือซ้ำ (Unique Procedure):** ท่าเรือเดียวกัน + เอเย่นต์เดียวกัน + ประเภทงานเดียวกัน ต้องมีคู่มือหลักเพียงอันเดียวเท่านั้น หากมีหลายสถานการณ์ให้สร้างเป็น **Variant (เงื่อนไข)** ย่อยแทน
2. **ข้อมูลสำคัญต้องเด่นชัด:**
   - เวลาตัดรอบ (Cut-off Time)
   - วิธีการชำระเงิน / อัตราค่าบริการ
   - ข้อควรระวัง (Special Notes) เช่น "ต้องโทรยืนยันหลังส่ง LINE ภายใน 15 นาที"
3. **รูปภาพต้องเป็นหน้าจอจริงและมีคำอธิบาย:**
   - รูปภาพขั้นตอนต้องมีช่อง `caption` เพื่อชี้จุดสำคัญ เช่น "กดปุ่ม 'อนุมัติ' สีเขียวมุมขวาบน"
   - ต้องรองรับการแนบมากกว่า 1 รูปในขั้นตอนเดียว
